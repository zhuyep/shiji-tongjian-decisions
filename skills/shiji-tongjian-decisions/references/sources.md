# 来源与检索

## 本次库如何确定

固定书目是《史记》《资治通鉴》。平台优先级：本轮明确指定的版本/文件 > 用户仍有效的项目来源配置 > [默认访问渠道](library.json)。未指定电子文本平台不构成缺少必要信息，不因此提问或停工。可在两书的不同电子文本之间查找，记录实际所用版本、覆盖范围和访问状态。

默认优先访问维基文库《史記》《資治通鑑》正文，按卷页面检索；可改用中国哲学书电子化计划（ctext.org）或有出处的本地两书文本。网站名称不自动保证底本质量；正文、后人注释、网站编辑标题分别辨认。检索只提供线索，先打开正文再写结论。换版本复核时分别列出异文，不把多个版本拼成一段所谓原句。

## 在线工作路径

1. 用宿主搜索/浏览工具限定当前选用的文本网站与书名。先用机制词，再用候选人物、古代用语及繁简/异体变体；保存实际查询。
2. 打开命中卷篇，读决策前因、建议、所选行为及后续记载。只有片段时不声称读完整卷。
3. 提取页面卷次、篇名/纪名和原纪年/段落锚点。优先保存页面“固定链接”的 oldid；未取得时保留 URL、访问日期与“未固定在线版本”。
4. 原文短摘逐字核验；换字、补标点、现代译文不能包装成原句。对记载冲突并列来源；不要为一致而改写原文。
5. 如果保存快照，用下述工具登记。若正文可经浏览工具获得而本地下载超时，使用浏览工具的实际可见正文保存片段并注明提取范围；不关闭 TLS 校验，不把错误页作为正文。

找不到引用时，先检查“于/於、后/後、强/彊、吴/呉/吳”等。变体仅用于查找，输出仍用所选版本原字。另一版本命中的句子应署另一版本，不能记作旧版本核验通过。用户明确要求只用某底本时遵守其范围。

## 本地原文工具

`scripts/corpus.py` 仅用 Python 标准库，无外发、无爬虫、无向量模型。每条 source 是一个卷篇或标明范围的片段。导入的是 UTF-8 文本快照，原文件不改写；扫描件先做 OCR 并人工核验关键引句，不能把 OCR 置信度当原文可信度。

以下以 Skill 所在目录为工作目录，示例路径由实际任务替换：

```bash
python3 scripts/corpus.py add --corpus /absolute/path/corpus \
  --library-id wikisource-zh-shiji-tongjian --id shiji-041 \
  --file /absolute/path/source.txt --book 史记 --volume 卷四十一 \
  --chapter 越王勾践世家 --source-url 'https://zh.wikisource.org/wiki/史記/卷041' \
  --edition '维基文库电子文本，底本未核' --locator '范蠡节' \
  --coverage '仅指定段落，非完整卷' --revision 2018395

python3 scripts/corpus.py search --corpus /absolute/path/corpus \
  --library-id wikisource-zh-shiji-tongjian \
  --term '范蠡' --term '去|歸|归' --window 2 --limit 6

python3 scripts/corpus.py verify --corpus /absolute/path/corpus \
  --library-id wikisource-zh-shiji-tongjian --id shiji-041 \
  --quote '君行令，臣行意。'
```

重复 `--term` 表示不同关键词组须同时出现在一个上下文窗口；组内 `|` 表示字面词任选其一，不是任意正则。检索结果给出原文窗口、元数据和行号，只是词面召回，不提供语义相似度或人生成功率。不同段落之间可能没有连续因果关系，仍须读原文判定。

`verify` 默认逐字检查；`--normalize` 只提示忽略空白/标点后是否命中。`normalized_only` 不是可交付引文，必须改回源文本原字原标点再验证。不会繁简转换；不会将替换过的字算 exact。

导入时 source ID 不可覆盖，内容变更建立新 ID/版本。读取前检查 SHA-256；文件被修改即返回错误，不继续输出“已核验”。库 ID 不一致即停止，避免拿上次缓存冒充本次指定库。哈希保护的是快照一致性，不保证来源元数据正确；元数据仍要与网页核对。

## 证据状态与停止条件

- **已核源**：在指定版本正文中找到该段，出处与上下文对应；历史可信度仍需分析。
- **待核实**：候选故事或引文尚未取得原文，不进入正式历史事实表。
- **数据源不可用**：网络、权限或文件不可读；输出缺口与可以继续的现实分析。
- **本次未找到近例**：报告实际检索覆盖，不说史无此事。

有限缓存中检索无命中，先查两书在线正文其他部分；用户要求离线或可用原文渠道均不可达时才停在覆盖边界。不得用第三部古籍或现代故事代替两书证据。
